  • Tests (test_minimax_h3_vdn.py, test_hybrid_window_h3_attention.py, 107 H3 tests pass), bench presets vdn-h3 / vdn-h3-fp8, CI case vdn_h3_t2va_4gpu_h100, cookbook §7 + “VDN-H3 on B200” table, backend docs, catalog entry.

4. Project A: branch-parallel Ulysses needs 8 GPUs

OpenVDN’s shipped 8-GPU layout puts the two branches on disjoint rank groups: 5 softmax ranks and 3 linear (VDA) ranks on B200 (6+2 on H200). Standard Ulysses gives every rank H/8 = 7 heads of both branches; branch-parallel gives softmax ranks 11 to 12 heads of the window softmax and linear ranks 18 to 19 heads of the recurrence, so each kernel runs at a friendlier size and the two branches overlap across ranks. Their measured gain: 1.629 → 1.425 s/NFE (6+2 vs 5+3 sweep) on 8× B200; 2.68 → 2.61 on 4 GPUs.

The forward and reverse exchanges are the only collectives besides the frame-mean all-reduce. Both branches still see the complete sequence; nothing is approximated.

Softmax rank payload

  • q, k already QK-normed and RoPE’d on the row shard with the row-local cache (as base H3 does), v, and gate_sm [rows, heads] → 3·128+1 per head.
  • Compute: HybridWindowAttentionH3Impl.forward_varlen on [T, h_i, 128] with the request metadata; gate epilogue.

Linear rank payload

  • Raw q, k, v (pre-norm, pre-RoPE), β [rows, heads], and only the 128-wide output_gate.down(x) hidden; the rank applies output_gate.up for its own heads (VDN sends the hidden, not the 7168-wide gate).
  • Compute: MiniMaxH3VDNLinearBranch(..., heads=slice(a, b)) exactly as the standard path does; text rows travel with the payload (they are ordinary rows).

Where it goes in SGLang

  • Entry point: _minimax_h3_hybrid_attention_core_impl in runtime/models/dits/minimax_h3.py. Add a sibling _minimax_h3_branch_parallel_core_impl selected when attention_backend_config["vdn_softmax_ranks"] is set; keep the standard core untouched so the 4-GPU numbers stay reproducible.
  • Groups: the SP group is get_sp_group() (runtime/distributed/parallel_state.py); its device_group is the NCCL group for torch.distributed.all_to_all_single(..., input_split_sizes, output_split_sizes). Create two sub-groups once with torch.distributed.new_group(ranks) (softmax ranks, linear ranks) for the overlapped variant; the simple variant uses a single uneven all-to-all over the SP group with per-destination split sizes (zero for the other branch’s fields).
  • Packing: sglang.kernels.ops.diffusion.pack_qkv_destination_major (layout/ulysses_qkv_triton.py) is the existing destination-major pack for 3 tensors; extend it (or write a sibling) to pack the per-branch field lists into one send buffer with per-rank byte splits. OpenVDN’s _pack_branch_target_kernel in src/inference/ulysses_runtime.py is the reference (also dispatch_fields_to_branches_overlapped, branches_to_sequence, balanced_splits).
  • Head splits: balanced_splits(56, softmax_ranks) and balanced_splits(56, world − softmax_ranks); a rank’s branch kind and head range are fixed for the request. The branch already accepts heads=slice; VDNFrameAlpha, VDNShortConv and the text state slice per-head parameters internally.
  • Frame mean: keep the async all-reduce over the SP group (partial sums of the row shard), wait before the branch.
  • Output: the reverse uneven all-to-all returns [rows, 56, 128] for each branch to the row owner; then out_proj and to_out_linear exactly as today (two GEMMs, FP8-friendly because each branch keeps its own activation scale).
  • Admission: VDNH3PipelineConfig.validate_server_args should require 1 ≤ vdn_softmax_ranks < ulysses_degree, TP = 1, ring = 1, and reject BCG/compile as today. Log the layout once next to the “VDN-H3 hybrid attention:” line in _maybe_prepare_hybrid_h3_metadata.

On 4 GPUs a 3+1 split makes the linear rank the straggler (≈ 36 ms of branch for all 56 heads + its GEMMs vs ≈ 30 ms on a softmax rank), which is why it was not built there. On 8 GPUs with 5+3 (scaling the 7-head figures above, so treat these as estimates): a linear rank holds ≈ 19 heads of the branch (≈ 24 ms) and a softmax rank ≈ 11 heads of the window attention (≈ 18 ms), against ≈ 13 ms of both per rank under standard Ulysses8; the split only wins if the freed overlap and the friendlier kernel sizes beat the heavier uneven exchange (≈ 1.7× the standard payload, since processed and raw q/k both travel). That is exactly OpenVDN’s finding: 5+3 beat 6+2 on B200 because the exchange, not compute, binds. First run standard Ulysses8 with the current code to get the baseline profile, then decide the split from it (OpenVDN saw 5+3 beat 6+2 on B200 because the exchange, not compute, binds).

Acceptance: (1) test_branch_head_slice_equals_full_run still passes; (2) a 2-rank mini test with 1+1 split against the standard core on the small ragged layout (bitwise-close, since the math is identical per head); (3) end-to-end 8× B200 FP8 at the paper workload: PSNR vs the standard-Ulysses8 output in the 23 to 25 dB band, and s/NFE below both standard Ulysses8 and OpenVDN’s 1.40.

  • Proposal: on SM100 with dynamic activation scales, quantize weights per-tensor at load and dispatch to torch._scaled_mm with scalar scales; guard by an Fp8Config option so the default channelwise path is unchanged. Validate on VDN-H3 and base H3: block parity in the fp8 harness (sgl_block_attn.py --fp8, per-tensor vs channelwise), then end-to-end PSNR vs the channelwise render. OpenVDN documents that fp8 changes the sample; expect the same.
  • Same file: fuse SwiGLU with the activation quant for fc2 (OpenVDN’s swiglu_quantize_activation): a Triton kernel producing fp8 + scale from the fc1 output, and an input_prequantized path that accepts it (today only per-tensor prequantized input is accepted). ≈ 1 ms per block on 1 GPU.
  • Expected: 6 to 8% on the 4-GPU step; it is also what closes the single-GPU gap (7.49 vs 6.47 s/NFE): in bf16 SGLang already matches OpenVDN’s tuned bf16 (7.86 vs 7.91).

7. Pitfalls that cost time

  • pkill matches your own shell. Use pgrep -f "[p]attern" and kill by PID, or the bash running the command dies with exit 144.
  • Never benchmark while another job holds the GPUs; microbenchmarks moved 2× under a background run.
  • Formatter-rewrapped anchors. Patching with literal string matches after pre-commit (ruff, isort, clang-format) fails silently if the file was rewrapped; use marker-bounded region replacement.
  • H3 warmup is a 5 s clip unless --warmup-num-frames / --warmup-resolutions are passed (the generic builder also rewrites req.num_frames from the VAE geometry; the H3 lowering reads the flag).
  • Memory on 1 GPU. BF16 DiT resident does not fit the paper clip (cuDNN internal error inside the depthwise conv is the symptom of workspace exhaustion).
  • Pushing. Git uses the forwarded SSH agent; when the socket dies, find a live one (for s in /tmp/ssh-*/agent.*; do SSH_AUTH_SOCK=$s ssh-add -l; done) and set git config core.sshCommand "ssh -o IdentityAgent=<socket>". A bundle and patch series of the branch are at /scratch/backup/ on the devbox.
  • HF token is needed only to re-upload the overlay (HfApi().upload_folder(folder_path=".", repo_id="kevin-mi/VDN-H3-overlay") from the overlay dir; delete any __pycache__ first), then re-pin the sha in model_overlay.py.
  • Pre-existing test failures on this torch 2.13 / B200 stack are listed in §3; do not chase them.
